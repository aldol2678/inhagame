# NOTI-01C-A · 서버 확인 최근 활동 연동

상태: 첫 단계 구현 후보, Draft PR. 영구 알림 보관함이나 실시간 푸시 서버가 아니다.

## 기존 권위 재사용
- 기존 Hub Messages 클라이언트의 `get_my_hub_conversations_v1`가 확인한 대화의 **마지막 활동**만 표시한다. 사용자별 `other.userId`, 대화 ID, 업데이트 시간, 실제 서버 미읽음 수를 사용하고 메시지 본문은 새로운 알림 저장소나 UI에 복사하지 않는다.
- 기존 World Social 클라이언트의 `get_my_world_social`가 확인한 **현재 받은 친구 요청**만 표시한다. 친구 요청 생성 시각은 반환되지 않으므로 임의 시간이나 과거 친구 수락 기록을 만들지 않는다.
- 위 목록은 서버의 현재 상태를 조회하는 **최근 활동 보기**다. 과거의 모든 메시지 발신, 친구 요청 취소나 수락 이력을 지속 보관하지 않으며, 앱을 닫거나 다른 계정으로 변경하면 메모리에서 제거한다.
- 기존 오늘의 알림(메시지 미읽음 집계, 출석, 퀴즈), 계정별 로컬 읽음 표시와 설정은 그대로 유지한다.
- 최근 메시지에서 **대화 열기**는 기존 Phone Messages에 서버 ID `recipientId`를 전달해 해당 대화를 연다. 친구 요청에서 **친구 요청 보기**는 기존 Phone을 닫고 World 친구 패널을 연다. 수락·거절·읽음 완료 등 서버 쓰기 작업은 기존 각 앱에서만 수행한다.

## 보안·동시성
- 새 RPC, SQL, 보상 부여, Realtime 구독, Push API, Service Worker를 추가하지 않는다.
- 최근 활동 탭을 실제 눌렀을 때만 서버 읽기를 시작한다. 화면에 다시 진입하면 재조회, 사용자가 명시적으로 새로고침 가능. 백그라운드 폴링 없음.
- 계정이 바뀌거나 스마트폰 화면에서 벗어나면 세대 토큰을 증가시키고 미완료 결과는 무시한다. Hub Messages는 기존 모델의 account generation을 함께 확인한다.
- UUID, 날짜, 서버 상태를 검증한 제한된 목록만 출력한다. DOM은 textContent를 사용하고 메시지 본문·친구 상세정보·추측 알림을 표시하지 않는다.
- 한 소스만 성공하면 성공한 데이터만 부분 표시하고 미확인 소스가 있음을 알린다. 둘 다 실패하면 재시도 안내를 표시한다.
- 서버에서 오래된 메시지나 차단된 대화가 더는 보이지 않으면 기록 목록도 사라진다. 이는 영구 이벤트 내역이 아니기 때문이다.

## 검증
- 단위 테스트: 서버 응답만 표시, 타 계정 데이터 차단, 동시 응답 세대 안전, 대화 열기와 친구 패널 딥링크, 미보관 메시지 본문, 실패·부분 실패.
- CI: GitHub 필수 verify 및 기존 Phone 브라우저 게이트 유지. 무관한 워크플로 재실행이나 성능 기준 하향은 하지 않는다.
- 승인 전까지 main 병합·Production 배포하지 않는다. 앱 내 실제 안드로이드/아이패드 PWA 테스트 필요.

## 후속 단계
**NOTI-01C-B**를 별도 DB 이벤트 원장으로 구현하려면 이벤트 ID 중복 방지, 서버가 정한 소유권과 RLS, 기존 메시지/친구 RPC 원자성, 페이지네이션, 계정 삭제 및 보관 정책, 개인정보와 수신 거부, 기존 데이터 backfill 금지 등을 우선 설계하고 실증해야 한다. NPC/퀘스트/동아리 이벤트는 각 기능의 권위 있는 이벤트 계약이 준비되기 전까지 가짜 기록을 만들지 않는다. NOTI-02 Web Push는 선택적 동의·서버 VAPID·디바이스 수명주기 검증 후 별도 실증한다.
