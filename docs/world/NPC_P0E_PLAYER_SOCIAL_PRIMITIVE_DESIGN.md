## 1. 목표와 제품 경계

NPC가 살아 움직이는 캠퍼스에서 플레이어가 **주변 사람을 발견 → 인사 → 관계 맺기 → 함께 이동 → 필요하면 차단·신고**할 수 있게 한다. P0-E의 여섯 구성요소는 `Nearby / Emote / Accompany / Friend / Block / Report`다. 파티, 글로벌 사용자 검색, 다른 구역 친구의 실시간 위치, NPC와 플레이어의 공용 친구 모델은 범위에 넣지 않는다.

완료 기준은 기존 버튼을 나열하는 것이 아니라, 같은 Place Zone에서 두 플레이어가 만나 안전하게 한 목적지까지 함께 갈 수 있는 흐름이다. 동행은 **제안과 수락이 있는 한 번의 여행**으로 정의한다. 기존 `FollowController`의 친구 자동 따라가기는 재사용하되, 그 자체를 상호 동행 완료로 간주하지 않는다.

## 2. 현재 자산과 빠진 부분

| 요소 | 현재 구현 | P0-E에서 할 일 |
| --- | --- | --- |
| Nearby | 원격 아바타·이름표, 미니맵 점, 현재 구역 인원 표시 | 반경 내 플레이어 목록과 프로필 진입점 |
| Emote | 손 흔들기·박수·웃기·춤·사진 자세, 구역 내 일시 전파 | Nearby에서 손 흔들기 진입점과 안내 문구 |
| Accompany | 수락된 친구 1명을 로컬에서 따라가기. 목적지·초대·상호 종료 없음 | 목적지 제안/수락, 나란히 이동, 도착/해산 |
| Friend | 프로필 카드에서 요청/수락/거절/취소/삭제 | Nearby 및 동행 진입점과 연결 |
| Block / Report | 계정 기반 RPC, 신고 사유 4종, 운영 검토 흐름 | 동행 즉시 중단, Nearby에서 제거, 기존 카드 재사용 |

주요 재사용 위치: `world-online.js`의 Presence 샘플, `player-card.js`, `social-client.js`, `follow-controller.js`, `emotes.js`, `navigation-state.js`, `campus-navigation.js`, 미니맵 POI 레지스트리. 원격 좌표는 시각 표현용 클라이언트 선언 값이므로 보상·권한 판단에 쓰지 않는다.

## 3. 사용자 흐름

1. 로그인한 플레이어가 캠퍼스에서 `주변`을 연다. 현재 Place Zone의 15m 안에서 실제로 보이는 플레이어만 거리순으로 표시한다. 친구 표시는 덧붙이되 정확한 좌표나 숫자 거리는 노출하지 않는다.
2. 한 사람을 누르면 기존 프로필 카드가 열린다. 친구 요청·차단·신고는 카드의 기존 작업을 그대로 수행한다. `👋 근처에 손 흔들기`는 기존 `wave` 감정표현을 실행한다. 이것은 지정 상대에게 보내는 개인 메시지가 아니라 주변에 보이는 동작이다.
3. 수락된 친구가 같은 구역에 있고 도보 상태라면 카드에서 `함께 가기 제안`을 누른다. 제안자는 캠퍼스 POI 중 한 곳을 선택한다. 일반 지도 핀, 실내 목적지, 잠긴 목적지는 P0에서 선택하지 않는다.
4. 상대에게 `OO님이 △△까지 함께 가자고 해요`가 표시된다. `수락` 또는 `거절`을 고를 수 있고, 응답하지 않으면 60초 뒤 사라진다. 제안을 받았다는 사실만으로 캐릭터가 움직이지 않는다.
5. 수락하면 두 사람의 지도 안내가 같은 POI를 가리킨다. 제안자가 길을 이끌고 수락자는 이동 보조로 약 1~2m 옆/뒤를 유지한다. 양쪽에 상대·목적지·`그만두기`가 보인다. 수락자의 직접 이동 입력은 즉시 보조를 끈다.
6. 두 사람이 목적지 도착 범위에 2초 이상 함께 있으면 `도착했어요`를 보여주고 동행을 끝낸다. 한 명이 먼저 도착하면 잠시 기다리는 상태로 남는다. 캠퍼스 구역 경계에서는 최대 6초 재연결을 기다리고, 서로 다른 구역에 남거나 상대를 놓치면 해산한다. `그만두기`, 차단, 친구 해제는 즉시 해산한다.

친구가 아닌 사람에게는 프로필 카드의 친구 요청까지만 제공한다. 기존 `같이 가기` 버튼은 혼동을 줄이기 위해 `친구 따라가기`로 표시하고 유지한다. 이 버튼은 목적지 공유가 없는 개인 이동 보조임을 설명한다.

## 4. Nearby 상세 규칙

- 자료원은 현재 구역 Realtime Presence와 최근 포즈 샘플이다. `online.miniMapRemotes()`처럼 읽기 전용 스냅샷을 제공하되, 목록에는 `userId/sessionId/displayName/presence/pose`만 필요한 범위에서 복사한다. 별도 검색 API나 저장 테이블을 만들지 않는다.
- `present` 상태, 유효한 포즈, 동일 Place Zone, 본인 아님, 내가 차단하지 않은 계정만 포함한다. 같은 계정의 여러 세션은 현재 보이는 한 세션으로 합친다. `suspect` 또는 포즈가 사라진 대상은 즉시 목록에서 뺀다.
- 진입 반경 15m, 이탈 반경 17m를 초기값으로 둔다. 거리 판정은 `worldToMeters`를 사용한다. 목록은 0.5초 단위로 갱신하고 거리순 최대 8명까지 보여준다. 동점은 `userId`로 정렬해 행 흔들림을 줄인다. 숫자 거리 대신 `가까이`/`조금 멀리` 정도만 표시한다.
- 목록의 `주변 N명`은 **현재 구역·반경 안의 다른 플레이어 수**다. 기존 로비의 `현재 구역 N명`과 뜻이 다르므로 합산하지 않는다. 로딩, 주변에 없음, 연결 끊김, 실내, 게스트 상태에 각각 별도 빈 상태를 둔다.
- 목록 행에서 카드를 열기 직전 현재 세션과 계정을 다시 확인한다. 사라진 경우 `지금은 이 플레이어를 볼 수 없어요`로 끝낸다. 닉네임은 표시용이며 행동 대상은 UUID다.
- 위치 목록은 열린 동안만 갱신한다. 다른 구역 친구를 `오프라인`으로 추정하지 않는다. 차단당한 사실도 추정하거나 표시하지 않는다.

## 5. 동행 상태와 권한

### 상태 전이

`IDLE → OFFERED → ACTIVE → ARRIVED/ENDED/EXPIRED`. `OFFERED`는 제안자에게 취소 가능, 수신자에게 수락/거절 가능하다. `ACTIVE`는 양쪽에 하나만 허용한다. 거절, 만료, 네트워크 실패는 이동을 시작시키지 않는다. 종료된 세션이 재접속으로 자동 재개되지는 않는다.

### 서버 기록

새 `world_accompany_sessions` 테이블은 `id`, `inviter_id`, `invitee_id`, `place_zone_id`, `poi_id`, `state`, `created_at`, `expires_at`, `accepted_at`, `ended_at`, `ended_reason`만 보관한다. **좌표·대화 내용·동선은 저장하지 않는다.** 제안은 60초, 활성 동행은 최대 10분으로 제한하고 만료 기록은 주기적으로 정리한다.

기존 Social S1-C1 방식처럼 행 직접 쓰기를 막고 서버 RPC `propose_world_accompany`, `respond_world_accompany`, `end_world_accompany`, `get_my_world_accompany`만 제공한다. 호출자는 항상 `auth.uid()`로 결정한다. 제안/수락 시 영구 계정, 이용 제한, 수락된 친구, 양방향 차단, 자기 자신 여부, 참여 중인 다른 동행을 재검사한다. 한 사람당 제안 대기 1건·활성 동행 1건, 재제안 쿨다운과 서버 측 속도 제한을 둔다. 응답은 수신자만, 종료는 참여자만 가능하다. 연속 탭·재시도는 멱등 처리한다. 사용자에게는 상대가 나를 차단했는지 알 수 있는 세부 오류를 반환하지 않는다.

Place Zone과 POI ID는 제안자가 보낸 힌트이므로 권한 증명으로 쓰지 않는다. 서버는 `AREA_*` 형식과 허용된 캠퍼스 POI ID를 검사하고, 클라이언트는 제안/수락 시 실제 Presence·현재 구역·POI 사용 가능 여부를 다시 확인한다. 목적지 후보는 지도 레지스트리의 공개된 캠퍼스 POI 중 보행 접근이 검증된 항목으로 한정한다. 초기 후보는 정문, 본관, 인경호, 정석학술정보관이며 실제 경로 검증 후 확정한다.

수신 알림은 `get_my_world_accompany`의 서버 확인을 통과한 제안만 화면에 보인다. 첫 구현에서는 캠퍼스 접속 중 5초 간격으로 조회한다. 현재 구역 Realtime 브로드캐스트가 발신자를 충분히 인증하지 않으므로 초대 신호를 그 채널에 싣지 않는다. Preview에서 지연과 부하를 측정해 필요하면 서버 확인을 유지하는 알림 힌트를 후속으로 추가한다.

### 로컬 이동과 안내

- 수락자가 `FollowController`의 이동 보조를 사용한다. 별도 직접 좌표 쓰기나 순간이동은 없다. `ACTIVE` 모드에서만 원격 캐릭터 진행 방향을 기준으로 약 1.2m 옆, 0.5m 뒤의 목표점을 계산한다. 통행 장애물/계단/연못은 기존 `PlayerController` 충돌과 막힘 감지에 맡긴다. 측면 유지가 불안정하면 기존 1.5~2m 추종 거리로 돌아간다.
- 두 사람 모두 기존 `NavigationState`로 같은 POI를 안내받는다. 동행이 시작될 때 기존 개인 목적지는 메모리에 보관하고, 정상 종료 시 원래 목적지를 복원할지 묻는다. 동행 중 지도에서 다른 목적지를 고르면 동행은 종료된다. 퀘스트·투어 목표는 건드리지 않는다.
- 양쪽 도착은 각 클라이언트가 자신의 위치와 상대의 **시각용 포즈**를 이용해 화면 경험으로만 판단한다. 도착 판정은 보상이나 업적에 사용하지 않는다. 상대 포즈가 오래되었으면 도착을 확정하지 않는다.
- 수락자의 직접 이동·점프·탑승·앉기·감정표현·NPC 대화 시작, 어느 쪽의 로그아웃·친구 해제·차단·텔레포트·실내 진입·막힘·10분 만료는 보조를 해제한다. 캠퍼스 Place Zone이 바뀌면 마지막으로 보인 위치까지 이동하며 최대 6초 동안 두 사람의 같은 새 구역 재합류를 기다린다. 해산 알림은 상대에게도 전달되며, 알림을 놓쳐도 서버 상태/Presence 재확인으로 수렴한다.
- NPC F 상호작용, 좌석, 탈것, 지도의 기존 우선순위를 유지한다. 동행은 전용 상태 배지와 `그만두기`로 조작하고 F를 새로 점유하지 않는다.

## 6. UI와 접근성

`social-cluster`에 `주변` 버튼을 추가한다. 데스크톱과 모바일 모두 같은 패널을 사용하며, 열린 패널은 기존 `worldActionsSuspended` 규칙에 포함해 이동키가 버튼 조작과 충돌하지 않게 한다. 행은 키보드로 선택할 수 있고, 상태 안내는 `role=status`, 초대 도착 알림은 `aria-live=polite`로 읽는다. 새 알림은 채팅 입력이나 NPC 대화 중 화면을 가리지 않고 작은 배지로 쌓인다. 패널을 닫아도 동행 상태 배지와 취소 버튼은 남는다.

차단 직후 Nearby 행·초대·동행 상태를 즉시 지우고 기존 채팅 제거 동작을 유지한다. 신고는 기존 프로필 카드의 사유 선택과 `report_world_user`를 사용한다. 신고만으로 상대의 아바타를 숨기거나 동행을 자동 종료할지는 사용자에게 명시된 동작이어야 하므로 P0에서는 **신고는 접수만**, 차단은 즉시 단절로 둔다.

## 7. 구현 순서와 파일 경계

1. **E1 주변 발견**: `world-online.js`에 읽기 전용 Nearby 스냅샷, `social/nearby-players.js`에 순수 필터·정렬, `social/nearby-panel.js`와 캠퍼스 HTML/CSS에 패널. 프로필·손 흔들기·차단 갱신 연결.
2. **E2 동행 권한**: Supabase migration/RPC 및 SQL 권한 테스트, `social/accompany-client.js`에 상태 조회·멱등 요청·오류 매핑. 기존 친구/차단 이벤트와 연결.
3. **E3 동행 월드 흐름**: `social/accompany-controller.js`에 상태 전이, `FollowController`의 선택적 측면 목표, `NavigationState` 목적지 연동, 프로필 카드의 제안/수락 UI, 상태 배지와 취소 버튼.
4. **E4 검증**: 두 브라우저 실제 계정으로 Preview 확인 후 범위와 이동 체감 조정. E1은 E2/E3와 분리 배포 가능하지만 **E 전체 완료 표시는 E3와 수동 검증 후** 한다.

## 8. 검증 기준

- 단위: 15m/17m 경계, 구역·셀프·차단·`suspect` 필터, 중복 세션, 닉네임 변경, 목록 진입 대상 사라짐.
- SQL: 익명/차단/친구 아님/자기 자신/중복 제안/초과 제안/만료 제안/타인의 응답·종료를 거부하고, 직접 테이블 쓰기와 타인 기록 읽기를 막는다. 보안 정의 함수의 고정 `search_path`와 grants 계약을 지킨다.
- 상태: 수락 전 자동 이동 없음, 제안 재전송 멱등, 동시에 서로 초대할 때 하나만 활성, 짧은 캠퍼스 구역 전환에서는 유지·6초를 넘긴 이탈이나 재접속·차단·친구 해제·연결 끊김·10분 만료에는 해산, 늦은 알림 무시.
- 이동: 플레이어 직접 입력이 즉시 우선, 충돌·연못·계단에서 끼임 시 안전 종료, 목적지 도착 후 자연 해산, 기존 개인 지도 안내 및 NPC/좌석/채팅 입력과 충돌 없음.
- Preview 수동 시나리오: A와 B가 인경호에서 만나 손을 흔들고 친구가 된 뒤 본관으로 동행한다. B가 수락 전 가만히 있는지, 이동 중 나란히 보이는지, 도착 후 둘 다 종료되는지, B가 중간에 직접 움직이거나 A를 차단하면 즉시 멈추는지 데스크톱/모바일에서 확인한다.

## 9. 출시 판단과 남은 결정

초기 수치(15m 주변 반경, 60초 초대, 10분 여행, 1.2m 측면 간격)는 **설계 가정**이다. Preview 체감과 부하로 확정한다. 우선 결정할 사항은 (1) P0-E에서 상호 수락 동행까지 포함할지, (2) 제안 가능한 POI의 최종 목록, (3) 동행 종료 뒤 이전 개인 목적지를 자동 복원할지다. 이 문서는 **상호 수락 동행 포함**, **검증된 캠퍼스 POI만 허용**, **복원 여부를 묻기**를 권장한다.

첫 구현은 제안 가능한 POI를 정문·본관·인경호·정석학술정보관으로 제한하고, 종료 후 이전 목적지를 다시 안내하는 버튼을 제공한다. 서버 세션은 만료 후 최대 1일 내 삭제하도록 정리 작업을 등록한다.
