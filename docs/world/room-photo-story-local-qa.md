# 방의 한 장면 · 로컬 구현 후보

## 기준과 범위

- 기준: `8cd48fa7a26df8112b7135e2f5b37c68f75bb75e` (PR #349, main 기반 `e299136b43a4be65f1feb1dc2a911241ad578a8a`).
- 이 변경은 #349의 보유 가구 추천, 방 조명·커튼 위에 적용하는 후속 패치다. 원격 commit/push/PR/merge/deploy와 DB 변경은 하지 않았다.
- 기존 내 방 HUD, 가구 편집기, PhotoMode, 스마트폰 앨범을 연결하는 입실 세션 내 안내다. 새 퀘스트·보상·화폐·구매·공유·영속 액자를 만들지 않는다.
- 조명·커튼은 기존 근접 F/터치 행동으로 직접 조절한다. 자동 이동이나 원격 스위치 조작을 추가하지 않는다.

## 사용자 흐름

1. 내 방 HUD의 `방의 한 장면`을 연다. 공부/휴식 분위기를 고른다.
2. `보유 가구로 미리보기`는 기존 편집기에 선택한 추천을 전달한다. 소유권과 인벤토리 확인이 준비돼 있을 때만 미리보기 배치를 적용한다. 인벤토리가 로딩 중이면 확인 후 기존 추천 버튼으로 직접 적용한다.
3. 가구를 한두 개 옮기거나 회전한다. 기존 `저장`만 서버의 가구 배치를 확정한다. `완료 · 빛과 구도로`를 눌러 이어가며, 저장하지 않은 변경은 기존의 계속 편집/버리고 닫기 확인을 거친다. 추천 없이 현재 배치로 진행하는 선택도 있다.
4. 출입문 옆 스위치와 창문 앞 커튼 안내를 읽고 방에서 조절한다. 준비되면 같은 내 방 메뉴를 다시 열어 사진 단계로 간다. 현재 빛을 그대로 사용할 수도 있다.
5. 원하는 자리에 서거나 앉고 기존 사진 모드를 연다. 기존 구도·카메라 이동·화각·촬영 동작을 그대로 사용한다.
6. IndexedDB 저장과 readback이 성공한 그 사진의 ID로 기존 스마트폰 앨범을 연다. 앨범 이미지의 실제 load 성공을 확인한 뒤에만 안내를 완료 처리한다.

새 안내는 실제 방 주인 계정이고 owner 역할인 내 방에서만 노출·시작된다. 방문자/게스트는 이 안내에 들어갈 수 없다. 기존 일반 PhotoMode의 방문자 촬영 기능은 그대로 유지한다. 실제 개인 방 입장 권한이나 게스트 방 생성 경로를 새로 열지는 않는다.

## 저장·취소·수명주기 계약

- 안내 상태는 메모리에만 있다. 방/계정/방 주인/역할 변경, 퇴장, pagehide에서 초기화한다. Back/Forward 복원으로 이전 안내나 캡처 성공을 되살리지 않는다.
- 현재 가구 배치를 유지하거나 미리보기를 취소해도 자동 저장하지 않는다. 저장 실패·미소유·pending 상태는 기존 가구 편집기가 처리하며 닫기 확인을 우회하지 않는다.
- persisted pagehide(BFCache)에서는 가구 draft·Undo/Redo·pending save·입력 소유권을 일반 편집과 동일하게 보존하고, 만료된 안내 continuation만 해제한다. 복귀 후 기존 저장/취소를 이어갈 수 있다. 실제 문서 종료에서는 guided 편집기를 기존 forceClose로 정리한다. 일반 편집기의 기존 동작은 바꾸지 않는다.
- 방의 실제 ID, 계정, owner, 역할, 안내 generation, 매 shutter마다 발급한 capture ticket이 모두 일치해야 사진 결과를 받는다. 이전 사진 성공은 다음 촬영 시도를 시작하면 이어받지 않는다.
- 기존 캡처는 반복 클릭과 늦은 PNG 인코딩을 막는다. 촬영 후 이미 시작된 같은 계정의 로컬 앨범 저장은 카메라를 닫은 뒤 마무리될 수 있다. 이 경우 이전 안내를 완료시키지 않는다. 계정 전환은 기존 앨범 epoch/transaction 취소로 격리된다.
- 저장 실패는 완료로 표시하지 않으며, 기존 PNG 직접 저장 경로를 유지한다. 앨범 열기 실패·이미지 로드 실패도 완료로 표시하지 않는다.
- 정확한 saved record를 사용해 다른 탭의 최신 사진이나 기기 시계 순서가 방금 찍은 사진을 대신하지 못하게 한다. 뒤로가기는 앨범 목록으로 돌아간다.
- 사진 원본과 썸네일은 기존 기기/브라우저/계정별 로컬 IndexedDB에만 저장한다. guest scope는 같은 브라우저의 공용 guest 저장소다. 자동 업로드·친구 공유는 없다. ephemeral room capture ticket은 앨범 레코드에 저장하지 않는다.
- 입력은 기존 InputFocus 정책으로 차단/해제한다. 닫기·취소·다른 모달 takeover 및 외부 UI handoff에서 숨긴 안내 버튼으로 키보드 초점을 돌려놓지 않는다.

## 검증 상태

- 전체 World Node 테스트와 `node apps/world/qa.mjs`를 실행했다. 최종 정확한 수와 패치 해시는 별도 로컬 결과 파일에 기록한다.
- 변경 JS syntax 검사와 `git diff --check`를 실행했다.
- 소스 독립 리뷰에서 제기한 정확한 사진 ID, 앨범 Back stack, 실제 이미지 로드 후 완료, guided 전용 pagehide, destroy 후 재활성 방지 문제를 반영했다.
- Chromium 직접 launch가 `socket() failed: Operation not permitted`로 종료됐다. 따라서 실제 WebGL 개인 방 사진 픽셀, 모바일 세로/가로 레이아웃, 실기기 사진 저장은 **미검증**이다. Node 통과나 fixture 소스 작성이 브라우저 합격을 뜻하지 않는다.
- 브라우저 fixture는 합성 2D 장면과 합성 가구 RPC를 쓰는 UI/로컬 저장 통합용이다. 실제 3D 방 렌더링 증거가 아니다.
- 전체 저장소 `scripts/public-ci.sh`, DB 검사, hosted CI, Production은 실행하지 않았다. 변경 영역은 World 클라이언트다.

## 브라우저 후속 확인

소켓/브라우저 사용이 허용된 환경에서 기존 pinned browser dependencies를 설치한 뒤 실행:

```sh
node apps/world/tests/browser/room-photo-story-smoke.mjs
```

별도로 실제 개인 방에서 소유자/방문자, 앉은 자세, 배치 충돌, 조명·커튼, 카메라 충돌, 계정 변경, 브라우저 Back/Forward, 저장 공간 부족 및 모바일 세로/가로를 확인해야 한다. 게임 운영 계정이나 운영 데이터 대신 합성 테스트 계정/로컬 서비스로 진행한다.
