# 인덕 서바이벌 · 스테이지 1–4

`index.html`은 단일 HTML/Three.js 게임입니다. Stage 1 인경호, Stage 2 본관, Stage 3 정석학술정보관과 Stage 4 5호관을 플레이할 수 있습니다. Stage 5~6은 준비 중입니다. 이 디렉터리가 독립 서바이벌 사이트의 정적 루트입니다.

## Stage 4 · 5호관

- 5남 1층 입구에서 시작하여 00:35 이후 5남 B1 인쇄물, 01:30 이후 5동 2층 강의 출석, 02:55 이후 1층 중앙 방어 16초를 완료합니다. 03:40 이후 5북 1층 출구에서 클리어, 04:45에 마감됩니다.
- 게임 내 두 계단 경로로 각 층을 왕복합니다. PC에서는 F/G, 모바일에서는 계단 부근의 층 이동 버튼을 사용합니다. 층별 적·탄환·XP·회복 드롭은 재방문 시 보존되고, 현재 층만 전투를 갱신합니다.
- 2차 진화는 인쇄물과 출석 완료 후 01:55부터 레벨 8 이상, 또는 02:25 이후 선택할 수 있습니다. 스테이지 4 궁극기는 선택 후 02:45에 열립니다.
- **실제 현장 안내도가 아닙니다.** 5남·5서·5북·5동의 구분은 학교 자료를 참고했고, 각 출입구·복도·계단 연결과 목표 위치는 플레이용 각색입니다. 제공된 `관련 배관도면.pdf`의 12쪽은 515A/515B 주변 공사 부분도면이어서 전체 층 동선의 근거가 될 수 없습니다.

## INHAGAME 계정 진행도

- 비로그인 기록은 이 브라우저의 기존 `inha-duck-survival-progress-v2` 저장소에 남습니다.
- 기존 INHAGAME 영구 계정으로 로그인하면 GAMES Supabase의 `user_game_progress`에서 `inha-duck-survival` 진행도를 읽고, 클리어와 최고 처치를 계정별로 저장합니다. 랭킹 기록은 별도의 검증 체계가 필요합니다.
- 동일 계정의 이 기기 기록만 자동 합칩니다. 비로그인 기록은 로그인 후 **이 기기의 게스트 기록 가져오기** 버튼으로 명시적으로 가져옵니다. 다른 계정의 로컬 기록을 자동 합치지 않습니다.
- 계정 확인이 불가능하거나 동기화에 실패해도 게스트 플레이와 기기 기록은 유지합니다. 동기화는 계정 화면에서 다시 시도할 수 있습니다.
- 인증에는 공개 가능한 Supabase publishable key와 RLS가 적용된 `get_my_game_progress` / `save_my_game_progress` RPC를 사용합니다. 서비스 비밀 키를 클라이언트에 넣지 않습니다.

## 검증 범위

`npm test`(단위 검사와 `node verify-stage4.cjs`)로 층별 출입구·목표·출구 도달성과 출입구 양방향, 구문 검사로 JavaScript 로딩 가능성을 검사합니다. 실제 모바일 기기에서 조작, 스테이지 4 완주, FPS 및 세로 HUD 검증은 별도로 필요합니다. 변경은 서바이벌 프로젝트에서 Preview 확인 후 운영 배포합니다.

## CI

공개 CI(`scripts/public-ci.sh`, 필수 체크 `verify`)가 `apps/survival/**` 변경에 대해 실행합니다. `npm run check`(구문·스크립트 참조), `npm test`(스테이지 명세·진행도 단위 검사, 공용 허브 진입 스크립트 `apps/world/game-entry.js` 단위 검사, Stage 4 경로 검사), `npm run test:e2e`(Chromium 스모크: 부팅, Stage 1·3·4 시작, 잠금 스테이지 대체, `ih_entry` 도착·플레이 보고)를 수행합니다. 브라우저 검사는 모든 요청을 `tests/offline.cjs`가 저장소 파일로 응답하고 그 외 요청은 차단하므로 운영 도메인이나 Supabase를 호출하지 않습니다. `package.json`과 테스트 파일은 `.vercelignore`로 배포에서 제외됩니다.
