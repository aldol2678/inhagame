## Reproduce checks

Use Python 3.11+ and Node 20+ in an isolated environment. Install `tools/requirements.txt`, then from this directory run:

```sh
python tools/check_semantics.py
node tools/check_oracles.mjs
sha256sum -c SHA256SUMS
```

The first checker validates all schema documents and the full corpus envelope, and exercises all 244 authored status/reason expectations. The Node checker independently computes normalization/canonical bytes/digests for 168 applicable canonical-output cases, all 252 manifest entries, and host profile/request bindings. The Python generator uses the separate RFC8785 0.1.4 package. Reject and count-only tests have explicit null encoding outputs; they are still tested by the semantic harness.

`python tools/build.py` deterministically rebuilds the generated schemas/registry/corpus/manifest from authored inputs and the included old corpus; it does not regenerate CONTRACT.md, reports or checksums. It imports no production evaluator. Expected semantic results are authored in the builder, not generated by the checker. After intentional artifact edits, rerun checks and refresh report/checksums. Do not run the generator as part of an implementation's expected-result calculation.

The small reference checker is not a production TML runtime and is not a proof for inputs outside its corpus. A conforming implementation must obey the complete normative contract, not merely hard-code these vectors. Rust/C++/WASM implementation conformance has **not** been tested or claimed. No legacy JS regression is counted as language-neutral contract conformance.
