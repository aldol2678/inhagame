# INHAGAME Campus P1 · 허브 화면·계정·랭킹·설정 상세 사양 v0.1

**상태: CANDIDATE · PLANNING ONLY · NON-CANONICAL**  
**작성 기준: 2026-09-25 KST / `feat/inhagame-campus-p0`**  
사용자 선택: 캠퍼스 3구역 확장 전에 메인화면, 계정·랭킹, 설정, 다른 인하오리 게임 연결을 먼저 기획한다. 이 문서는 구현·출시 승인이나 공식 로드맵 채택을 뜻하지 않는다.

## 1. 목표와 현재 경계

첫 방문자는 GPU 초기화에 앞서 허브에서 무엇을 할 수 있는지 보고, 한 번의 동작으로 캠퍼스 또는 공개된 다른 게임에 들어간다. 계정 사용자는 같은 사용자 정체성을 확인하고, 각 게임의 검증된 랭킹을 따로 본다. 게임 목록은 등록정보에 따라 갱신하되 테스트 중인 게임은 승인 없이 공개되지 않는다.

- P0 캠퍼스는 `apps/world` 기능 브랜치의 Preview이며, P0-01~05 코드는 구현됐으나 WebGL2·카메라·전체 Zone 동선 등 기기 QA가 남아 있다. `main` 반영과 `inhagame.example` 연결은 이 사양의 자동 후속행동이 아니다.
- 현재 `main`의 게임 앱: `apps/classic`, `apps/induckup`, `apps/survival`. 공용 Supabase `public.games`의 조회 시점 상태는 Classic `production`, 인덕업·서바이벌 `testing`.
- 계정용 `user_game_progress`와 인덕업 계정 연결 코드가 존재하지만, 허브 회원가입 완료·서브도메인 간 자동 로그인·다른 게임의 랭킹 제공을 의미하지 않는다.
- 도메인 후보: `inhagame.example` 허브와 캠퍼스; `duck.inhagame.example` Classic, `induckup.inhagame.example` 인덕업, `survival.inhagame.example` 서바이벌. 연결 여부와 목적지 HTTP 응답은 출시 전 각각 다시 검증한다.

## 2. 정보구조 및 첫 화면

`/` = GPU를 시작하지 않는 2D 허브. `/campus` = 캠퍼스 입장 경로 후보. 랭킹·계정·설정은 허브 내 패널 또는 경로로 구현하되 브라우저 뒤로 가기와 직접 접근이 가능해야 한다.

1. 상단: INHAGAME 로고, 게스트/계정 상태, 설정 진입.
2. 첫 화면의 주 행동: **캠퍼스 입장**. 3D 엔진은 이 행동 뒤에 로드한다. 실패하면 허브로 돌아와 재시도할 수 있다.
3. 인하오리 게임 카드: 공개 게임의 이름, 간단 설명, 상태, 플레이 버튼. 게임 카드가 없거나 목록 API가 실패해도 캠퍼스 입장은 유지한다.
4. 랭킹 미리보기: 게임을 선택하면 그 게임의 모드별 기록을 열람한다. 점수 단위가 다른 게임을 합산한 통합 순위를 만들지 않는다.
5. 계정 패널: 게스트, 이메일 인증 대기, 정식 계정, 로그인 실패를 구분한다.

### 핵심 사용자 흐름

| 흐름 | 시작 → 종료 | 예외 처리 |
|---|---|---|
| 첫 방문·게스트 | 허브 → 캠퍼스 입장 → 돌아와 게임 카드 선택 | GPU 불가 시 허브와 다른 게임 링크 사용 가능 |
| 가입·로그인 | 계정 열기 → 기존 인증 흐름 → 상태 확인 → 허브 복귀 | 메일 지연·기존 계정·세션 만료 표시, 게스트 데이터 보존 |
| 랭킹 조회 | 게임 선택 → 지원하는 모드 탭 → 공개 순위·내 순위 | 미지원·빈 결과·조회 실패를 서로 다른 상태로 표시 |
| 다른 게임 이동 | 카드 선택 → 해당 서비스로 이동 → 서비스의 허브 복귀 링크 | 목적지 오류 시 카드 비활성화/오류 안내; 인증 토큰을 URL에 담지 않음 |
| 설정 | 설정 열기 → 실제 지원 항목만 변경 → 재방문 | 저장 실패 시 기존 값 유지·오류 안내 |

## 3. 기능 계약과 통과 기준

### H01 · 허브와 캠퍼스 진입

- 모바일과 데스크톱에서 제목, 계정 상태, 캠퍼스 입장, 게임 목록, 랭킹·설정 진입을 화면 크기에 맞게 제공한다.
- 첫 화면은 WebGPU·WebGL2가 없어도 열린다. 캠퍼스 입장 전에는 PlayCanvas 그래픽 장치를 생성하지 않는다.
- 캠퍼스 입장/복귀, 로딩·오류·재시도, 브라우저 뒤로 가기를 확인한다.
- **PASS:** GPU가 없는 환경에서도 허브와 외부 게임 링크를 쓸 수 있고, 지원 환경에서 캠퍼스 입장 후 P0 조작을 유지한다.

### H02 · 게임 카탈로그와 바로가기

- 공용 `games` 등록정보에서 공개용 필드만 제공하는 별도 목록 계약을 둔다: `slug`, 표기명, 설명/썸네일, HTTPS 목적지, 서비스 상태, 공개 승인 여부, 랭킹 지원 모드.
- 기본 공개조건은 **공개 승인 + 서비스 상태 production + 목적지 검증 통과**의 조합이다. 테스트 중인 앱은 테스터용 Preview에서만 선택적으로 노출한다. 등록만으로 공개하지 않는다.
- 새 게임은 등록정보와 공개 게이트를 채우면 허브 코드 수정 없이 다음 목록 갱신 시 카드에 나타난다. 오탈자·타 도메인 URL·retired/paused 상태는 자동 노출하지 않는다.
- **PASS:** 새 승인 게임의 카드가 허브 코드 배포 없이 표시되고 정확한 서비스로 이동한다. testing/retired 게임은 일반 허브에 표시되지 않으며, 목록 API 실패 시 오류·재시도 화면이 나온다.

### H03 · 계정과 진행도

- 기존 Supabase Auth/게임별 진행도 계약을 재사용한다. 허브에서 게스트 상태와 정식 계정 상태를 명확히 표시하며, 가입·로그인·로그아웃은 계정 작업의 완료된 흐름을 연결한다.
- 게스트 → 신규 계정, 게스트 → 기존 계정의 진행도 병합/충돌 정책을 데이터 종류별로 검증한다. 사용자에게 무통보 덮어쓰기를 하지 않는다. 정식 계정이 아닌 경우 클라우드 진행도 접근권한을 확대하지 않는다.
- 같은 Supabase 프로젝트를 쓰는 것과 다른 서브도메인에서 자동 로그인되는 것은 별개의 문제다. 안전한 세션 전달 방식을 검증하고, 성공하기 전에는 SSO를 제공한다고 표시하지 않는다.
- **PASS:** 신규·기존 계정, 게스트, 세션 만료, 로그아웃, 기기 재방문, 각 서브도메인 이동을 실기기에서 확인한다. 기존 게임 진행도가 사라지거나 타인의 진행도가 노출되지 않는다.

### H04 · 게임별 랭킹

- 1차 연동 대상은 Classic의 일반전·랭킹전 공개 기록. 각 게임별 랭킹 API 계약과 기록 검증 기준을 분리한다.
- 인덕업·서바이벌은 검증된 랭킹 소스가 준비되기 전에는 **랭킹 준비 중**으로 표시한다. `user_game_progress`는 사용자가 저장하는 진행도이며 경쟁 랭킹의 권위 점수로 쓰지 않는다.
- **PASS:** Classic의 모드 전환·공개 순위·가능한 경우 내 순위가 기존 게임 결과와 일치한다. 미지원 게임, 빈 순위, 서버 오류가 구별되고 다른 사용자의 비공개 진행도는 읽히지 않는다.

### H05 · 설정

- 초기 구현은 실제 동작하는 항목만 노출한다. 캠퍼스 화면 품질(자동/낮음/높음), FPS 목표(자동/30/60), 조이스틱 크기·위치 등은 적용 효과를 확인한 뒤 제공한다. 기기가 60 FPS를 낼 수 없을 때 숫자를 보장하는 문구를 쓰지 않는다.
- 소리 설정은 소리 기능이 연결된 범위에서만 활성화한다. 허브 공통 설정과 게임별 설정의 소유 영역을 명시한다.
- **PASS:** 변경 직후 실제 동작이 바뀌고 새로고침 뒤 설정이 남는다. 계정 동기화가 추가된다면 게스트/계정 간 충돌과 각 게임의 적용 범위를 따로 확인한다.

### H06 · 복귀 동선과 출시 QA

- 허브에서 모든 공개 게임으로 이동한다. 각 게임의 **허브로 돌아가기**는 해당 게임 앱의 별도 변경이 필요하며 담당 앱 Preview에서 각각 검증한다.
- **PASS:** 모바일·데스크톱에서 모든 공개 링크가 정상 열리고 돌아오기 동선이 있다. 외부 링크와 계정 세션 경계, 랭킹 권한, 설정 저장을 확인한다. URL 문자열의 인증정보 유출이나 임의 도메인 이동이 없다.
- P0 캠퍼스의 미완료 기기 QA와 허브 QA를 각각 유지한다. `main` 병합·도메인 연결은 별도의 출시 판단이다.

## 5. 결정이 필요한 항목

- 허브의 코드 위치: 기존 `apps/world`에서 첫 화면을 분리하는 방식이 현재 유력하다. 별도 앱 신설은 배포·인증 경계상의 이점이 확인될 때만 검토한다.
- 공개 카탈로그의 읽기 계약: 기존 `games` 테이블 전체를 브라우저에 개방하지 않고, 공개가 승인된 필드만 반환하는 경로와 장애 시 표시를 정한다.
- 서브도메인 인증의 실제 방법과 기존 인덕업 계정 구현의 재사용 단위는 회원가입 작업의 실기기 QA 이후 확정한다.
- 설정의 계정 간 동기화, 인덕업·서바이벌 랭킹 규칙, `inhagame.example` 연결일은 본 후보에서 미확정이다.
